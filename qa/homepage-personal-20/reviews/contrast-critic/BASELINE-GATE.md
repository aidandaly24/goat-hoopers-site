| Full-page silhouette and composition | 01 has a genuine left rail and the shortest member page. 02 has a horizontal header and a longer staged scroll. 03 has a broad notebook column with a companion panel. | Actual typography | 01 uses Barlow Condensed headings, Arial reading/controls, Plex data. Its body default is 16px, but most working notes, table rows and controls are roughly 11–13px; section headings are about 34px. 02 uses Space Grotesk headings, system sans reading/controls and Plex data: 44px title, 56px main scores, but roster names about 14px and prices/controls about 13px. 03 uses Georgia reading/headings, Arial controls and Plex data: 17px prose, 15–17px player names, 13px roster numbers, many 10–13px labels/utilities. Authors must make reading, control, and data roles deliberate and comfortably readable; increasing only headlines/scores fails. Distinct type roles need distinct density, measure, spacing and weight decisions. Shared Plex throughout the set cannot substitute for independent data typography. |
| Information priorities | Reaves consistently gets matchup, completed-week evidence and quote coverage. Neural changes the data, yet all three turn missing quotes into a prominent opening assignment, then repeat coverage/missing-score/no-model explanations. This makes source maintenance the team's identity. Unknown score, partial quote coverage and absent model stay honest and easy to inspect where relevant; they are supporting context, not a chore to resolve or the brand. Guest gets an engaging public league with clear real account entry and no claimed private team. |
| First three useful actions | 01 Reaves: inspect matchup, inspect counted players, review roster quotes. 02 Reaves: inspect matchup evidence, read player evidence, inspect quote coverage/full roster. 03 Reaves: read the new player breakdown, inspect a counted player, inspect the companion matchup. Those are valid tasks, but their hierarchy and presentation converge. | On every persona, name the first three useful actions and show why their order suits that visitor. They must lead to substantive local content with understandable Back/close/focus behavior. A coverage warning is not itself a useful manager action. Do not fabricate lineup saves, trade submissions, login or live advice. Distinct authors may prioritize the same legitimate task, but must make different product/composition choices around it. |

A complete website still needs substantial initially visible normal-flow content, purposeful navigation/current location, and a semantic footer that helps the visitor continue. All existing destinations must remain discoverable sensibly. Completeness is not achieved by displaying every roster row, repeating synthetic/coverage caveats in every section, or hiding the homepage behind controls. Compact visible synthetic labeling plus accessible source explanation, known-zero versus unknown semantics, partial valuation limits, and historical manager/period qualifications remain mandatory.
