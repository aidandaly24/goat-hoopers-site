Stage one only. Source-ready grayscale structure, awaiting independent structure review. No full art, production change, publishing, Git action, external provider, installation or shared presentation code.

## Surface contract

**User question:** “What is happening to my team, and which names and stories should I follow?”

**Primary action:** Read the actual current pair and its saved pick; members have a visible My team link beside the opening identity. The text index directly addresses the other jobs.

**Default desktop geometry:** A single continuous paper field. The actual REAVES DROPPER name occupies the main horizontal measure; its known 0.0 and the other team's Pending score create the next line; Ware the Hoes At? closes the composition at the right. Saved choices form offset sentences. Member valuation becomes a very large number followed by flowing player/value paragraphs. Ten faces are a running name field. The team index unfolds into roster prose. Editorial headlines and exact stat strings change the typographic scale again. There are no content cards, bordered modules, repeated panel grid or sidebar.

**Default phone geometry:** The same field becomes a deliberately broken word poster. Large team names wrap; known zero and Pending occupy separate textual lines. The index becomes one native disclosure, keeping My team reachable in the first screen. Offsets reduce, complete roster references reflow into data paragraphs, and every visible link/control has at least 44px height. The phone does not shrink a desktop score table or turn panels into a repeated card stack.

**Forbidden patterns:** A novelty poster above a conventional dashboard; fake finality for incomplete scores; largest-probability selection replacing the actual returned choice; invented History/Power; public personal summary; clipped long names; decorative reveal gates.

## Why this changes the architecture

Names, values, zero and Pending are the composition rather than labels inside a presentation container. The same rule governs the whole experience: AI is a sentence with an unfolding receipt; valuation is a number with expanding name prose; faces form an inline collection; roster inspection inserts actual names into the typographic field; editorials shift scale using their actual claims. Navigation addresses words and regions within this field. This is more than a palette or section-order change.

The supplied craft notes changed specific choices:

- Hallmark custom-direction/macrostructure principle: carry the idea through the complete experience. It caused the roster, AI and tools to remain typography, with no generic dashboard below the opening.
- Elaya redesign principle: break equal-card symmetry and expand at the origin. Receipts and full rosters therefore open inline, and offsets follow actual sentence lengths.
- MoMA indexed-collection principle: make a name useful to find. The team field has real local search, ordering and direct roster addresses rather than being decorative oversized type.
- `pbakaus/adapt`: adapt the task on phone. The index folds, numerical/state lines separate, and real names break purposefully instead of shrinking to a compact multi-column scoreboard.
- Addy accessibility and the project navigation reference: native controls, explicit local-versus-profile actions, 44px phone controls and a tested enlarged-text path.
- Antfu explicit-import principle: only the shared fact module is imported; no shared renderer, CSS or runtime dependency.

## Motion job and fallback

Stage one is deliberately still: routine index jumps, query changes and focus responses are immediate. There are no timers, loops, observers, autonomous reveals or RAF loops. The one `requestAnimationFrame` at a direct hash load only performs the initial address scroll after rendering.

For a later full build, the only proposed motion is an occasional receipt/roster insertion that clarifies where text was added to the poster. Budget at most 180ms; essential content is readable at once, repeated keyboard actions remain immediate, interruption finishes at the requested open/closed state, and reduced motion uses the identical native still expansion. No motion implementation is authorized before the structure gate. This follows the supplied Emil/pbakaus purpose-and-frequency gate and iart still-equivalence guidance.
