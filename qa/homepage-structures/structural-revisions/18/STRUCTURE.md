# 18 structural revision — Compare the evidence

Grayscale structural revision only. The original `wireframes/18/` is preserved. This version is ready for a new independent structural review, not full art or final acceptance.

## Before and after

Critic B rejected original 18 against 01/05 because its pinned stage summarized the same long, anchor-addressed homepage. Reading or selecting a chapter changed a duplicate visual; it did not change the relationship among records. The retained original had six chapters in a roughly 12,000px desktop document.

This revision removes the chapter article, stage observer and chapter navigation. Its primary surface is a bounded comparison table. User-selected identities become columns; typed fields and source periods become rows. Pinning/removing a name changes the actual comparison and the available evidence intersections. Switching from **Compare players** to **Follow a team** changes the working composition from player measures to franchise relationships, including actual opponents, saved model opinions, standings and appearances in dated editions. There is no universal subject reader, chapter journey, branching question menu, diagram-to-shelf transition or quote-planning scenario.

Two candidates were sent before coding: an evidence comparison table and an evidence-sorting/reconciliation task. Parent selected the comparison table and explicitly requested plain product language, changing player/franchise relationships and a field-transposed phone view. No database terminology is exposed to visitors.

## Surface contract

- **User question:** Which facts can I put side by side about these players or teams, and where does the supplied evidence stop?
- **Primary action:** Pin up to three names, compare typed fields, or follow the selected players’ actual current teams.
- **Relevant states:** Two players; three players with different source coverage; franchise relationships; saved-pick records; searchable full league records; dated editorial records; derived comparison transcript; member-only valuation/form records.
- **Desktop geometry:** Compact identity and route access; one context switch; a native pin chooser; then a bounded table with the selected identities held as column headers. The evidence is in the cells, including explicit missing cells. Current/completed/form/dated rows remain in the same comparison rather than replacing one interchangeable reader.
- **Phone geometry:** The same data transposes by field. Each field header retains units/period; underneath it every pinned identity appears with that field’s value or missing-record statement. This lets readers compare a measure without horizontal panning or switching between whole player dossiers. The pin chooser starts closed at both sizes; names remain visible in the comparison headers and removable there. Source records stay in an independently scrollable, locally expandable register.
- **Forbidden patterns:** Arbitrary combined metrics; invented totals or history; treating a missing quote as $0 or proven unpriced; mixing NBA, college and fantasy-point measures; changing a 35% returned choice to the 65% alternative; a new linear homepage article beneath the comparison.

## Motion / still equivalent

Pointer pinning applies a 160ms grayscale background emphasis to the newly added column after the actual table has already recomposed. Its job is to identify which evidence was added; values and text are never hidden, delayed or tweened. Frequent mode switches, removal and keyboard activation are instant. Reduced motion makes the same composition immediately available without emphasis; changing the preference live cancels any active emphasis. There are no animation loops, timers, autonomous scroll changes, reveal observers or new dependencies.

The same table is readable without motion. The optional bounded transcript repeats the selected identities under each exact field scope and marks missing evidence. It does not create an event history or fabricated play-by-play.

Hallmark’s architecture principle changed composition and navigation, not the palette: the chapter/stage model is gone. `adapt` changed the comparative axis on phones rather than shrinking desktop columns. Elaya’s inline-expansion principle keeps source records local and independently open; source selection actually feeds the comparison. `accessibility` informs native input, visible focus, explicit scope, and a still/text equivalent. `animate` limits motion to explaining a real added column rather than decorating reading progress.
